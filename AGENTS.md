# Project Rules & Design Protocol

## UI & Design Changes Workflow
- **HTML Prototypes First**: Whenever the user requests design changes, visual alterations, layout adjustments, or new UI ideas, ALWAYS create an interactive standalone HTML mockup/prototype file first (served in `public/` and saved in artifacts).
- **No Premature Code Implementation**: NEVER edit project source code (`src/`) for design or UI layout changes until the user has reviewed, tested, and explicitly approved the HTML prototype.
- **Explicit Confirmation Required**: Interactive option selection or exploratory discussion does NOT constitute authorization to write production code. Always wait for explicit user confirmation before touching the codebase.
